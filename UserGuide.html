TuteeDex User Guide

TuteeDex is a desktop application for private tutors to manage student profiles, optimized for use through a Command Line Interface (CLI) while retaining the benefits of a Graphical User Interface (GUI). If you type quickly, TuteeDex can help you manage student information faster than traditional GUI applications.

Quick start

  1. Ensure that Java 25 or later is installed on your computer.
    Mac users: Ensure you have the precise JDK version prescribed here.

  2. Download the latest .jar file from here.

  3. Copy the file to the folder you want to use as the home folder for TuteeDex.

  4. Open a terminal, cd to the folder containing the JAR file, and run java -jar TuteeDex.jar.
    A GUI similar to the one below should appear in a few seconds. Note how the app contains some sample data.

  5. Type a command in the command box and press Enter to execute it. For example, type help and press Enter to open the help window.
    Some example commands you can try:

    • list : Lists all active contacts.

    • add n/John Doe p/98765432 a/John street, block 123, #01-01 d/10-Aug s/Maths day/MON time/15:30 o/20 : Adds a student profile named John Doe to TuteeDex.

    • delete 3 : Deletes the 3rd contact shown in the current list.

    • clear : Deletes all contacts.

    • exit : Exits the app.

  6. Refer to the Features section below for details of each command.

Features

Notes about the command format:

  • Words in UPPER_CASE are the parameters to be supplied by the user.
    For example, in add n/NAME, replace NAME with a value such as John Doe.

  • Items in square brackets are optional.
    For example, edit INDEX [d/START_DATE] can be used as edit 1 d/10-Aug or as part of an edit containing other optional fields.

  • Items followed by ... can appear zero or more times.
    This notation is used only when a command explicitly supports repeated values.

  • Parameters can be in any order.
    For example, if the command specifies n/NAME p/PHONE_NUMBER, p/PHONE_NUMBER n/NAME is also acceptable.

  • Extraneous parameters for help and clear are ignored.
    For example, help 123 is interpreted as help.

  • If you are using a PDF version of this document, be careful when copying and pasting commands that span multiple lines as space characters surrounding line-breaks may be omitted when copied over to the application.

Viewing help: help

Shows a message explaining how to access the help page.

Format: help

Adding a person: add

Adds a student profile to TuteeDex.

Format: add n/NAME a/ADDRESS p/PHONE_NUMBER d/START_DATE s/SUBJECT day/DAY time/TIME [s/SUBJECT day/DAY time/TIME]... [o/OUTSTANDING_AMOUNT] [t/TAG]... [notes/NOTE]

Note: START_DATE must use the DD-MMM format, for example 10-Aug. Calendar validity is not checked.

Note: OUTSTANDING_AMOUNT is optional and defaults to 0. It must be a nonnegative number with no more than two decimal places. Do not include a currency symbol, sign, separator, or exponent.

Note: At least one subject lesson is required for new profiles. Enter each lesson as s/SUBJECT day/DAY time/TIME, in that order. DAY is one of MON, TUE, WED, THU, FRI, SAT, or SUN (letter case is ignored), and TIME is a 24-hour start time in strict HH:mm format, such as 09:00 or 15:30. Each subject has exactly one weekly lesson. Repeat the complete triplet for multiple subjects. Subject names must be 1–50 characters after trimming surrounding spaces and may contain English letters, digits, spaces, and hyphens, including at least one letter or digit. A student cannot have two subjects with the same name, ignoring case. Comma-separated subjects are not supported.

Note: notes/NOTE is optional and stores one free-text note per student. Omitting it or supplying a blank value stores no note. Surrounding spaces are trimmed; internal spaces, punctuation, and display case are preserved. Specify notes/ only once. Repeating it is an error and no profile is added. As with other Add values, recognised field prefixes preceded by a space mark the next field, rather than literal note text. Notes are saved automatically and appear in view INDEX. Existing data without notes loads with empty notes.

Tags are optional descriptive labels, separate from subjects:

  • Supply one t/ prefix per tag, such as t/A-Level t/Needs revision. Omitting t/ creates a profile with no tags.
  • Tags accept letters (A-Z and a-z), digits, spaces, and hyphens. Surrounding spaces are trimmed, internal spaces are preserved, and tags are stored in lowercase.
  • Repeated tags, including case variants such as t/A-Level t/a-level, are combined. Tag order does not matter.
  • Every tag must be valid. Blank tags, including t/A-Level t/, reject the entire command with Tags must contain only letters, digits, spaces, or hyphens and must not be blank.

An add command is rejected as a duplicate when name, phone, address, start date, and outstanding amount match an existing profile, even if subjects, tags, or notes differ. Outstanding amounts are compared numerically, so 0, 0.0, and 0.00 are equivalent. A duplicate produces This contact already exists in TuteeDex and does not add another profile.

Examples:

  • add n/John Doe a/John street, block 123, #01-01 p/98765432 d/10-Aug s/Maths day/MON time/15:30
  • add n/Betsy Crowe a/Newgate Prison p/12345678 d/19-Sep o/600 s/H2 Chemistry day/TUE time/09:00 s/Physics day/FRI time/16:30
  • add n/Amy Bee a/Block 1 p/91234567 d/10-Aug s/Maths day/WED time/14:00 notes/Revise fractions
  • add n/Peter Parker a/Block 9 p/91234567 d/10-Aug s/Physics day/SAT time/10:30 t/A-Level t/Needs revision

Viewing a student profile: view

Format: view INDEX

Displays the name, phone, address, start date, outstanding amount, subjects with their weekly lesson day and start time, tags, and notes of the student at INDEX in the currently displayed list. A student with no note has an empty Notes: value. The index must be a positive integer and refer to a displayed student; otherwise, the command shows an error. Viewing a profile does not change student data or the current list.

Subjects, tags, and notes also appear on each contact card without running view. Subjects keep their stored order; tags appear alphabetically using their stored lowercase labels. Missing subjects or tags show Not specified; missing notes show an empty Notes: value. Long subjects, tags, and notes wrap within the card.

Exporting contacts: export

Exports all student contacts, including archived contacts, to a UTF-8 CSV file in the application's working directory.

Format: export

The generated file is named contacts-YYYYMMDD-HHMMSS-milliseconds.csv. Each contact occupies one row. The CSV contains the name, phone, address, start date, outstanding amount, subjects, tags, notes, and archive status. Multiple subjects or tags are joined with ; .

Importing students: import

Adds students from a CSV file written by export, for example to move students from another computer or to restore students you deleted. Importing never removes or changes the students already in TuteeDex.

Format: import FILE_PATH [confirm]

  • Without confirm, TuteeDex only checks the file and shows which students would be added. Nothing changes.
  • Add confirm at the end to add them. If any row has a problem, nothing is imported, so a file is never half imported.
  • The file must be inside the folder TuteeDex runs from (the folder with the JAR file), or a folder inside it. This is where export saves its files. For safety, TuteeDex does not read files anywhere else, so move or copy the file into that folder first.
  • FILE_PATH is relative to that folder, for example students.csv or term 4/students.csv. Paths with spaces work, with or without double quotes around them. Only .csv files are accepted.
  • The first row must be the header that export writes. Each following row is one student with the same 9 columns: name, phone, address, start date, outstanding amount, subjects, tags, notes and archived (true or false).
  • Subjects are written as SUBJECT (DAY HH:mm) and separated by semicolons, for example Maths (Mon 09:00); H2 Chemistry (Wed 11:30). Tags are separated by semicolons. A blank outstanding amount means 0, and blank tags or notes mean none.
  • Every value is checked with the same rules as add. Problems are listed by spreadsheet row number, for example Row 4: Phone numbers should only contain numbers, and it should be 8 digits long. Up to 10 problems are shown.
  • A row that is exactly the same as a student already in TuteeDex, or as an earlier row in the file, is skipped, so importing the same file twice is safe.
  • A row with the same name, phone, address, start date and outstanding amount as a stored student, but different subjects, tags, notes or archive status, is reported as a problem. Use edit to change the stored student instead.
  • Files saved by Excel work too, as long as the columns are not changed.
  • If you edit the file in a text editor, wrap any value that contains a comma, a double quote or a line break in double quotes, and write each double quote inside it twice, for example "Needs ""revision""". Spreadsheet apps such as Excel do this for you. A row with unbalanced or misplaced double quotes is reported as a problem instead of being imported with changed text.

Examples:

  • import contacts-20261024-175424-176.csv checks a file that export saved earlier.
  • import contacts-20261024-175424-176.csv confirm adds the new students from that file.
  • import "term 4/students.csv" confirm adds students from students.csv in the term 4 folder inside the TuteeDex folder.

Listing and filtering students: list

Shows active student profiles, or filters active profiles by one or more subjects or tags. Archived students are not shown. Each card displays the contact's name, phone, address, start date, outstanding amount, subjects, tags, and notes.

Format: list [-summary] [s/SUBJECT]..., list [-summary] [t/TAG]..., list -archived, or list -subjects

  • Plain list restores all active students, including after a Find or filter.
  • Supply one s/ per subject. A student matches if they take any requested subject. Subject names match completely, ignoring case: s/Maths does not match Additional Maths. Subjects use the same validation as Add; equivalent repeated values are combined.
  • Supply one t/ per tag. A student matches if they have any requested tag (OR matching). Match complete tags, ignoring case and surrounding spaces: t/Needs revision matches needs revision, but t/revision does not. Tags use the same validation as Add; equivalent repeated values are combined. Profiles without tags do not match.
  • Use either subject or tag prefixes in one command; mixing them is invalid.
  • Each filter searches all stored students, rather than just the current search results. Results retain their stored order. Indexes used by view, edit, and delete refer to the newly displayed list.
  • The status message reports the displayed count, for example Listed 2 contacts. or Listed 1 contact. A subject filter with no matches shows No contacts match the specified subjects.; a tag filter with no matches shows No contacts match the specified tags. Both leave the displayed list empty. Plain list on an empty address book shows No contacts stored. Use the add command to add one.
  • Blank or invalid values, uppercase or unknown prefixes, and unprefixed arguments such as list 3 are rejected. Invalid input leaves the displayed list and stored profiles unchanged. Listing never changes profile fields.
  • Add -summary to display total and paid counts for the displayed students, for example list -summary, list -summary s/Maths, or list -summary t/A-Level. The flag must be entered exactly as shown.

Examples:

  • list s/Maths s/H2 Chemistry shows students taking either subject.
  • list t/A-Level t/Needs revision shows students having either tag.
  • find Nobody followed by list t/A-Level still finds matching students in the full address book.
  • list shows every active student again.

Grouping students by subject

list -subjects switches the display to active students grouped under their subjects. Each subject group shows the students taking that subject and each student's own weekly lesson day and start time. Students taking the same subject at different times remain in one subject group. Subject headings are sorted alphabetically. Students within each group are alphabetical by default; an active sort applies within each subject group instead. Archived students are excluded. The option is standalone and cannot be combined with -summary, -archived, or s//t/ filters. Enter plain list to return to the normal student contact list.

view, help, and export preserve the current grouping and scroll position. Failed commands also leave the displayed list unchanged. Find and other List options switch back to the normal contact list for their results. Applying or resetting sort keeps the current grouped or ungrouped presentation; bare sort also preserves scroll position.

Listing archived students

list -archived displays only archived students, using the active sort or stored order by default. It replaces any previous search or filter and does not change saved profiles. Feedback is Listed 1 contact. or Listed N contacts.; if no archived students exist, the list is empty and feedback is No archived contacts..

Use -archived on its own. Combining it with -summary, subject/tag filters, or other arguments is not supported and shows an error without changing the current list. A standalone -archived token is reserved for this option and cannot be included as a separate word within a tag or subject filter value. Plain list returns to active students; subject/tag lists and summaries also continue to exclude archived students. For example:

  • archive s/Bob Choo, then list -archived, shows Bob in the archived list.
  • view 1 shows the first student in that displayed archived list.
  • list returns to the active list without restoring archived students.

Sorting the current display: sort

Format: sort FIELD/DIRECTION [FIELD/DIRECTION]..., sort, or sort reset

Supported fields are n/ (name), o/ (outstanding amount), d/ (start date), and slot/ (upcoming lesson). Supply 1 to 4 distinct fields, separated by spaces, with lowercase prefixes and asc or desc directions. The first field has highest priority; later fields resolve ties. A new Sort replaces the previous criteria. Bare sort reports the current order. Commands and the reset keyword are lowercase; sort RESET is rejected. sort reset clears the criteria without changing the filter or presentation. The ungrouped display returns to original stored order; the subject-grouped display returns to alphabetical students within each group.

  • Names are compared alphabetically without regard to case; amounts are compared numerically.
  • Start dates are compared by calendar month and day, without a year. Existing invalid dates stay last.
  • Slots use the next weekly start relative to the computer's local time. A start exactly now is due now; a start that has passed occurs next week. Lessons have start times, not durations.
  • In the ungrouped display, every student appears once, numbered 001, 002, 003, and so on in displayed order. slot/asc selects each student's nearest upcoming lesson, then orders students from nearest to furthest. slot/desc selects each student's furthest upcoming lesson, then orders students from furthest to nearest. Each row shows the selected subject and slot; all subjects remain stored. Equal slots use the first subject. Students without subjects show No lesson slot and stay last when compared by slot, in either direction.
  • After list -subjects, Sort orders lessons within each subject group while keeping headings alphabetical. Each lesson uses its own subject's schedule. Students can appear in several groups with the same student index. Students without subjects have no grouped rows, but remain in the unique student counts.
  • Use the printed student index. In the ungrouped display it is the row position. In subject groups it refers to the same current unique-student order, so group indexes may repeat and need not increase from top to bottom. View/Edit/Delete act on the whole profile; deleting a grouped entry removes that student and all their lessons. Total and paid counts count each student once.
  • Sort preserves the filter and student data. Find/List retain the sort; edits reorder students as needed. Full ties retain stored student order. Valid criteria work on an empty display.
  • Upcoming ordering refreshes on Sort, filter changes and profile changes. It does not move automatically as time passes; rerun Sort or List to refresh it. Bare sort and View do not refresh the reference time.
  • Invalid fields, directions, repeated fields or extra arguments reject the entire command without changing the current order, filter or presentation. Bare sort, View, Help and Export preserve the displayed panel. Sorting is currently session-only and resets on restart; preference persistence is a separate feature.

Examples:

  • sort o/desc n/asc puts the largest balances first, then sorts equal balances by name.
  • sort slot/asc n/asc shows students' nearest upcoming lessons first, breaking equal-slot ties by student name.
  • find Amy followed by sort d/asc sorts only the current search results.
  • list -subjects followed by sort slot/asc n/asc orders upcoming lessons within each subject group.

Editing a student profile: edit

Updates one or more fields of an existing student profile in TuteeDex.

Format: edit INDEX [n/NAME] [p/PHONE] [a/ADDRESS] [d/START_DATE] [o/OUTSTANDING_AMOUNT] [s/SUBJECT day/DAY time/TIME]... [t/TAG]... [notes/NOTE]

  • Edits the person at the specified INDEX. The index refers to the index number shown in the displayed person list. The index must be a positive integer 1, 2, 3, ...
  • After a search such as find Betsy, edit 1 ... edits the first search result.
  • At least one of the optional fields must be provided.
  • Existing values will be updated to the input values.
  • Fields that are not supplied remain unchanged, including the outstanding amount, tags, subjects, and notes.
  • Supplied subject lesson triplets replace the entire subject set. Repeat the complete s/SUBJECT day/DAY time/TIME triplet for multiple subjects. The triplet order, day names, time format, subject validation, and unique-name rule are the same as for add. Changing only subject case or order while keeping the same lesson slots is a no-op and retains the existing spelling and order.
  • Supplied t/TAG values replace the entire tag set. Repeat t/ for multiple tags. Tags use Add's validation and lowercase normalization; equivalent repeated tags are combined. A single blank t/ clears all tags. Mixing blank and nonblank tags, or repeating blank t/, is invalid.
  • notes/NOTE replaces the note. A blank notes/ clears it; omitting the prefix preserves the existing note. Surrounding whitespace is trimmed; internal spacing, punctuation, display case, and Unicode text are preserved. Specify notes/ only once. The prefix rules below also apply inside notes: a recognized field prefix starts another field, while an unknown prefix-shaped token is rejected. URLs such as https://example.com remain note text.
  • Field values use the same validation rules as add: names contain alphabetic characters and spaces, addresses are nonblank, phone numbers contain exactly eight digits, start dates use DD-MMM, and outstanding amounts are nonnegative numbers with at most two decimal places. Calendar validity is not checked.
  • Use o/0 to reset the outstanding amount to zero. Blank values for the five scalar fields, including o/, are invalid.
  • Leading and trailing spaces around values are ignored. Tags are normalized to lowercase; other text case and internal spaces are preserved.
  • The command word edit and all prefixes are lowercase and case-sensitive. Fields may appear in any order after the index, except that each subject's s/, day/, and time/ prefixes must stay together in that order.
  • Each single-valued field, including notes, may appear only once in an edit command. Tags accept repeated t/ prefixes, and subjects accept repeated s/ prefixes.
  • Unknown prefixes, including uppercase variants such as P/, are rejected. A letter-led token ending in / at the start of input or after whitespace is treated as a prefix even inside a value; a slash in #02/03 remains part of the address.
  • An edit is rejected as a duplicate only if name, phone, address, start date, and outstanding amount match another profile. Tags, subjects, and notes do not distinguish duplicates. Amounts are compared numerically, so 20, 20.0, and 20.00 are equivalent.
  • If any supplied field is invalid or the edit creates a duplicate, no fields are changed and the displayed list remains unchanged.
  • A changed profile produces Edited contact: <updated contact name>, refreshes its displayed values, and returns to the full contact list. The changes are saved automatically.
  • If all supplied values match the existing values, the result is No changes made to contact: <contact name> and the current displayed list is preserved.

Errors:

Input problem Feedback
Missing or invalid index INDEX must be a positive integer! (e.g., 1, 2, 3, …)
Index beyond the displayed list No matching contact found at the specified index.
No field supplied, e.g. edit 1 At least one field must be provided to edit.
Repeated single-valued field Each contact field may be specified only once in an edit command.
Unknown or uppercase prefix Invalid command format. followed by Edit usage instructions
Invalid field value The same field validation error as add
Duplicate profile This contact already exists in TuteeDex.

Examples:

  • edit 1 p/91234567 d/20-Oct edits the phone number and start date of the first profile.
  • edit 2 n/Betsy Crower edits the name of the second profile.
  • edit 1 o/600 changes the first profile's outstanding amount to SGD 600.00.
  • edit 1 o/0 resets the first profile's outstanding amount to zero.
  • edit 1 t/A-Level t/Needs revision replaces the first profile's tags with these two tags.
  • edit 1 t/ clears the first profile's tags while keeping its other fields.
  • edit 1 s/Maths day/MON time/15:30 s/H2 Chemistry day/THU time/17:00 replaces the first profile's subjects and lesson slots while keeping its other fields.
  • edit 1 notes/Revise fractions replaces the first profile's note while keeping its other fields.
  • edit 1 notes/ clears the first profile's note.
  • find Betsy followed by edit 1 a/32, Clementi Road updates only the address of the first search result.

Locating persons by name: find

Finds active students whose names contain any of the given keywords. Archived students are excluded, even when their names match. Searching does not change archive status or any other profile fields.

Format: find KEYWORD [MORE_KEYWORDS]

  • The search is case-insensitive; for example, hans matches Hans.
  • Keyword order does not matter; for example, Hans Bo matches Bo Hans.
  • The search considers only names.
  • Only full words match; for example, Han does not match Hans.
  • Persons matching at least one keyword are returned (an OR search); for example, Hans Bo returns Hans Gruber and Bo Yang.
  • Matching contacts appear once. Feedback shows Found 1 contact. or Found N contacts..
  • No matches produce an empty list with No contacts match the specified name keywords..
  • Each search replaces the previous filter. Plain list restores all active students.
  • Missing keywords cause an error without changing the current results or saved data.

Examples:

  • find John returns john and John Doe
  • find alex david returns Alex Yeoh, David Li

Deleting a contact: delete

Permanently deletes the specified student contact from TuteeDex immediately, without a confirmation prompt. The displayed contact list refreshes and the remaining contacts are renumbered.

Format: delete INDEX

  • INDEX is the one-based position in the currently displayed contact list, including search results.
  • INDEX must be one positive integer, such as 1, 2, or 3; no other parameters are accepted.
  • A successful command displays Deleted person: <contact details>.
  • If INDEX is invalid, the app explains that it must be a positive integer. If it is larger than the displayed list, the app reports that no matching contact was found.

Examples:

  • list followed by delete 2 deletes the 2nd contact in the address book.
  • find Betsy followed by delete 1 deletes the 1st contact in the results of the find command.

Archiving a student: archive

Archives a student without deleting the student profile. Archived students are hidden from list and are excluded from its summary counts, but their data remains saved in TuteeDex.

Format: archive s/STUDENT_NAME

  • STUDENT_NAME must contain letters and spaces and must begin with a letter.
  • The name must match the student's full name exactly, ignoring letter case. For example, archive s/john doe can archive a student named John Doe.
  • A successful command displays Student archived. and refreshes the active student list.
  • If no student with the specified name exists, the command displays Student cannot be found.
  • If the student is already archived, the command displays Student already archived.

Example:

  • archive s/John Doe archives John Doe and removes the student from the active list.

Unarchiving a student: unarchive

Restores an archived student to the active student list. Unarchiving does not change the student's profile details.

Format: unarchive s/STUDENT_NAME

  • STUDENT_NAME must contain letters and spaces and must begin with a letter.
  • The name must match the student's full name exactly, ignoring letter case.
  • A successful command displays Student unarchived. and makes the student appear in list again.
  • If no student with the specified name exists, the command displays Student cannot be found.
  • If the student is already active, the command displays Student already active.

Example:

  • unarchive s/John Doe restores John Doe to the active student list.

Clearing all entries: clear

Clears all entries from the address book.

Format: clear

Exiting the program: exit

Exits the program.

Format: exit

Saving the data

TuteeDex automatically saves data after every command. You do not need to save manually.

Editing the data file

TuteeDex data is saved automatically as a JSON file [JAR file location]/data/addressbook.json. Advanced users are welcome to update data directly by editing that data file.

Caution: If your changes make the data file invalid, TuteeDex starts with an empty address book at the next run. The invalid file remains on disk until you run a command (TuteeDex saves after every command). Still, we recommend backing up the file before editing it.
Furthermore, certain edits can cause TuteeDex to behave in unexpected ways (e.g., if a value entered is outside of the acceptable range). Therefore, edit the data file only if you are confident that you can update it correctly.

FAQ

Q: How do I transfer my data to another computer?
A: Install the app on the other computer and overwrite the data file it creates with the data file from your previous TuteeDex home folder.

Known issues

  1. When using multiple screens, if you move the application to a secondary screen, and later switch to using only the primary screen, the GUI will open off-screen. The remedy is to delete the preferences.json file created by the application before running the application again.
  2. If you minimize the Help Window and then run the help command (or use the Help menu, or the keyboard shortcut F1) again, the original Help Window will remain minimized, and no new Help Window will appear. The remedy is to manually restore the minimized Help Window.
  3. Data created before the student-profile schema change is not compatible. Delete the old address-book JSON file before starting this version of TuteeDex.
